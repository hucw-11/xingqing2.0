# 上游调查

调查日期：2026-11-16
调查方式：`git clone --depth 1` 只读调查，未运行任何上游构建脚本，未上传个人数据。
对应任务书：P0 / R02、R03、R04、R11、R12。

## 结论摘要

1. **上课**为 Kotlin/Compose Multiplatform，Apache-2.0，已具备课程、课表导入、WebDAV 快照备份和桌面端；但 Excel 只支持 **.xlsx**，旧版二进制 **.xls 明确不支持**，与任务书 R02 的假设不一致。
2. **Daily You** 为 Flutter/GPL-3.0-only（含 GPLv3 第 7 条附加条款），不能复制其代码进心晴 2.0，只能作为交互与数据语义参考。
3. **旧版心晴 1.2** 是可复用的自有 Kotlin 代码，已有课程重复展开、例外、冲突、提醒排期和单元测试；但**没有实现 JSON 导出/导入**，README 中的“设置与备份”仍是规划。
4. 两个上游都**不提供**“日程重复规则 + 例外实例”“日内多次心情记录”“双向同步合并”，这些必须自建，不能宣称可复用。
5. 上课的 WebDAV 是**整包快照备份/恢复**，不是双向合并；心晴 2.0 的同步协议需要独立设计。

## 2. 上课：能力清单

路径均相对上课仓库根目录。

### 2.1 课程与课表模型

| 能力 | 文件 | 现状 |
|---|---|---|
| 课程实体 | `shared/src/commonMain/kotlin/com/shangkeschedule/data/db/main/Course.kt` | UUID 主键、课表外键、名称、教师、地点、星期、节次或自定义时间、颜色、备注、学分、考核方式、实验课标记 |
| 课程周次 | `.../db/main/CourseWeek.kt` | 关联表存**显式周次集合**，支持任意周集合；比“起始周+持续周数+单双周”更灵活 |
| 作息节次 | `.../db/main/TimeSlot.kt`、`TimeSlotScheme.kt` | 节次时间方案，可多套 |
| 多课表 | `CourseTable.kt`、`CourseTableConfig.kt` | 多课表、学期开始日期、总周数、显示偏好 |
| 日程 | `.../db/main/ScheduleEvent.kt` | 按日期归属，分类 todo/activity/exam/homework/other，全天标记、起止时间、地点、备注、完成状态 |
| 待办 | `.../db/main/TodoItem.kt` | 按日期归属，可选时间、完成状态、排序权重 |
| 课程备注/成绩/培养方案 | `CourseNote.kt`、`Grade.kt`、`CurriculumCourse.kt` | 存在，但不在心晴 2.0 首版范围 |

关键缺口：

- `ScheduleEvent` / `TodoItem` **没有重复规则字段**，也没有“仅本次/之后/整个系列”的例外实例模型。
- 课程**没有单次停课/调课的例外表**（周次集合只能表达“哪些周上”，不能表达“某一周换成另一天/时间”）。
- 因此 R03 的重复日程、R04 的跨日/重叠处理、A03/A06 的实例身份，需要心晴 2.0 自建领域模型。

### 2.2 导入能力

| 能力 | 文件 | 现状 |
|---|---|---|
| Excel 网格解析 | `shared/src/commonMain/kotlin/com/shangkeschedule/data/parser/ExcelScheduleParser.kt` | 轻量 .xlsx 解析：okio 落盘 → `openZip` → 正则读 `sharedStrings.xml` 与第一个 `sheetN.xml`；支持共享字符串、内联字符串、富文本、稀疏行列、合并单元格回填；有行列数与解压体积上限 |
| 格式枚举 | `.../data/parser/ImportFormat.kt` | `TextImportFormat`：WAKEUP、PLAIN、JSON、CSV、ICS、HTML；**没有 XLS/XLSX 枚举**，Excel 由文件魔数单独分流 |
| 文本/文件解析 | `.../data/parser/UniversalScheduleParser.kt`（1070 行） | WakeUp 分享文本、WakeUp/Sleepy JSON、ICS、CSV、HTML 表格、纯文本；自动嗅探 + 指定格式两种入口；Excel 网格另有 `parseExcelGrid` |
| 文件入口 | `shared/src/commonMain/kotlin/com/shangkeschedule/ui/settings/import/TextImportViewModel.kt` | .xlsx 按 ZIP 魔数识别；**旧版 .xls 直接返回错误，提示另存为 .xlsx**（`tivm_error_old_xls`） |
| 文件选择 | `.../ui/settings/import/ImportEntryScreen.kt` | 选择器接受 `xlsx, xls, json, csv, ics, ical, html, htm, txt`，但 .xls 实际不可解析 |
| AI 导入 | `.../data/api/AiImportClient.kt`、`ui/settings/import/AiImportScreen.kt` | 上游有“让 AI 解析课表”的入口；心晴 2.0 明确不做 AI 自动改数据，不采用 |

结论：任务书 R02 写的“Excel 指 .xlsx / .xls”与上游实际能力不符。**“兼容上课原有导入格式”在本轮证据下等于：.xlsx + WakeUp 文本/WakeUp JSON/ICS/CSV/HTML/纯文本，不含 .xls。**

### 2.3 备份与 WebDAV

| 能力 | 文件 | 现状 |
|---|---|---|
| 备份仓库 | `shared/src/commonMain/kotlin/com/shangkeschedule/data/repository/BackupRepository.kt` | 模块化整包备份：COURSE / STYLE / APP_SETTINGS / USER_DATA；本地 zip 与 WebDAV 共用入口；带 `BackupMeta`、模块版本、快照 ID |
| 序列化 | `.../data/model/CourseImportExport.kt` | JSON + CBOR；`COURSE_SCHEMA_VERSION = 3`、`USER_DATA_SCHEMA_VERSION = 5`；`ignoreUnknownKeys`、`encodeDefaults` |
| WebDAV 客户端 | `.../data/api/webdav/WebDavClient.kt`、`WebDavConfig.kt` | Ktor + Basic Auth；连接 15 秒、请求 5 分钟；明文 http 仅告警不阻断；401 挑战后才发送凭据 |
| 云端目录 | `Backup/` 与 `Backup/snapshots/<id>/` | 整包文件覆盖/恢复语义 |

明确不能当作 2.0 同步协议的部分：

- 没有变更批次、设备序列、父版本、冲突副本或删除墓碑。
- 上传成功只代表文件写入，不代表其他设备已合并。
- 恢复是“用备份覆盖本地”的整包语义，不具备双向合并能力。

### 2.4 提醒

- 公共计划与身份：`shared/src/commonMain/kotlin/com/shangkeschedule/notification/plan/*`、`.../notification/identity/*`。
- 安卓实现：`shared/src/androidMain/kotlin/com/shangkeschedule/notification/**`，含早八/每周提醒、注册表、同步闸门、状态存储。
- 本轮只按文件与类型判断其存在，**未逐行核实精确闹钟、OEM 保活、通知渠道细节**；P1/P2 实现提醒时需要重新阅读。
- 心晴 2.0 的微信提醒走云端调度，不复用其本地提醒架构，只参考计划版本与幂等思路。

## 3. Daily You：能力清单

许可证为 GPL-3.0-only + §7 附加条款，**以下仅作为语义与交互参考，不复制代码。**

| 能力 | 文件 | 现状与可借鉴点 |
|---|---|---|
| 日记实体 | `lib/models/entry.dart` | `id`、`text`（Markdown）、`mood`（整数，可空）、`timeCreate`、`timeModified`；一条日记一个心情 |
| 心情量表 | `lib/models/mood.dart`、`mood_scale_level.dart`、`mood_scale_preset.dart` | 默认五档 1–5；量表每档可自定义标签、图标、颜色；有旧值迁移示例（-2..2 → 1..5） |
| 标签 | `lib/models/tag.dart`、`tag_category.dart` | 标签分类、图标、颜色、排序；`label` / `tracker` 两种类型；`entry_tags` 多对多 |
| 附件 | `lib/models/attachment.dart` | image/audio/video，按类型分目录，记录路径、排序、创建时间；支持大文件提示 |
| Markdown | `lib/markdown/markdown_parser.dart`、`markdown_blocks.dart`、`block_nodes.dart` | 自研块级解析 + `markdown_widget` 预览；编辑与预览共用正文 |
| 统计 | `lib/stats/entry_stats.dart`、`stats_analysis.dart`、`stats_range.dart`、`streaks.dart`、`stats_influence.dart` | 条目统计、范围统计、连续记录、影响分析 |
| 数据库 | `lib/database/app_database.dart` 等 | sqflite；显式 schemaVersion 与逐版本迁移；桌面用 `sqflite_common_ffi` |
| 平台 | 仓库根目录含 `windows/`、`macos/`、`linux/`、`android/`、`ios/` | 桌面端是真实交付目标 |

可借鉴的语义：

- 心情量表“档位 + 标签/图标/颜色”可配置，适合心晴 2.0 的“量表版本 + 原始值”设计。
- 附件独立于正文存储、按类型分目录、记录排序，适合 R05/A07。
- 标记“记录实际发生时间”与“系统创建/修改时间”分离（`timeCreate` vs `timeModified` 的用法），但 Daily You 只有一条时间，心晴 2.0 需要显式的 `occurredAt`。

不可采用：

- 一条日记一个心情，无法表达“一天多篇日记、每篇独立心情、另有独立快速心情记录”（R07/A08）。
- 没有日程/课程，也没有跨设备同步。

## 5. 导入格式矩阵（源码级结论）

| 格式 | 上课是否支持 | 证据 | 心晴 2.0 处理建议 |
|---|---|---|---|
| .xlsx | 是 | `ExcelScheduleParser.extractGrid` + `parseExcelGrid`；合并单元格回填；首个工作表 | 复用解析思路（Apache-2.0），配匿名样本测试 |
| .xls（BIFF 二进制） | **否** | `TextImportViewModel` 明确返回“旧版 .xls 请另存为 .xlsx”；解析器只认 ZIP 魔数 | 默认提示转换；若用户坚持，需另加解析库并单独评估 |
| WakeUp 分享文本 | 是 | `parseWakeUpShareText` | 可参考 |
| WakeUp / Sleepy JSON | 是 | `parseWakeUpJson` | 可参考 |
| ICS | 是 | `parseIcs`，含 RRULE 的 INTERVAL/COUNT/UNTIL | 可参考 |
| CSV | 是 | `parseCsv` | 可参考 |
| HTML 表格 | 是 | `parseHtmlTable` | 可参考 |
| 纯文本 | 是 | `parsePlainText` | 可参考；成功率取决于排版 |
| AI 解析 | 是（上游） | `AiImportClient` | 2.0 不采用 |

实测状态与后续安排：

- 本机没有 JDK/Kotlin/Gradle/WSL/Docker，无法在本地运行上游解析器；按 R15“尽量不安装本地安卓开发环境”，不为此安装工具链。
- 源码级矩阵已完成；实际执行放到 **P1 的 JVM CI 测试**与 **P2 的 A04 验收**，使用匿名样本，覆盖合并单元格、空行、周次文本、节次映射与错误码。
- `../课表.xlsx` 是个人数据，按任务书要求**未读取、未外发**；兼容性验证需要用户明确授权或提供匿名样本。
- .xls 已由用户确认首版不支持，只提示另存为 .xlsx。

## 6. 风险与未决项

1. **R02 的 .xls 预期与上游能力冲突**：必须先由用户确认策略，再承诺兼容。
2. 上课的导入布局识别基于启发式，不同学校模板需要样本回归；不能只凭 README 宣称“兼容”。
3. Daily You 为 GPL-3.0，任何代码复制都会传染许可；只能自研。
4. 上课的桌面端未进 CI，Windows 打包链路需要本项目自建并实测。
5. 上游使用较新的 Kotlin 2.4 / CMP 1.11 / AGP 9.3；本项目应在 P1 选择可稳定构建的版本组合，不盲目跟随最新。
6. 日程重复、实例例外、日内多次心情、双向同步、微信提醒均为自建能力，工作量需要按阶段估算。
7. 上课没有课程单次停课/调课例外；1.x 有但语义较窄；2.0 需要统一“系列 + 原始实例 + 例外”模型。
8. 本轮未验证上课的精确闹钟实现、Android 通知兼容性、桌面中文输入与 Markdown 手感；这些是 P1 spike 的内容。
