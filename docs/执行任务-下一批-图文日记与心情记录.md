## 1. 本批目标与完成标志

用户可以在安卓和 Windows 上：

1. 一天新建多篇独立日记，使用 Markdown 编写正文、插入多张图片。
2. 为日记添加多个自定义标签、五档心情及可选情绪标签。
3. 保存、重新打开、修改、搜索、删除日记；离开编辑页后能找回未发布草稿。
4. 不写正文，只记录一次心情和标签。
5. 关闭应用再打开，正文、图片、标签、心情及发生时间仍完整保留。

**一句话验收：写一篇带三张图片、两个标签和心情的 Markdown 日记，保存、关闭、重开、修改，内容和图片全部正确；当天再写第二篇，两篇独立存在。**

交付是实际可用的日记功能和双端产物，不是占位页面、只有实体类或只演示内存数据。

## 5. Markdown组件选择与实现原则

先查看项目已有依赖，再比较最多两个适合Compose Multiplatform的成熟方案，核实官方文档/源码中的Android、JVM支持、许可及Markdown能力。一页说明即可，不重新做全项目选型。

要求：

- Markdown原文是长期保存的真实数据，不能只存渲染后的HTML或内存中的富文本对象。
- 至少支持标题、段落、粗体/斜体、列表、引用、链接、代码块和本地图片。
- 编辑、预览切换不会丢失尚未输入完的内容；中文输入法组合文字不能被自动保存/格式化反复打断。
- 优先复用成熟编辑与渲染能力。若富文本组件往返转换会丢原文，允许使用Markdown源码编辑区＋常用格式工具栏＋成熟预览组件，不自行重写Markdown解析器。
- 格式工具作用于当前选区或光标位置；不得只在正文末尾随意追加符号。
- 先验证选择器、中文输入、三图预览、长文往返保存，再投入大量样式工作。
- 不套用CourseNote的2000字限制；至少以一万字日记验证编辑、保存和预览基本可用。
- 增加依赖需固定可复现版本，记录来源。不能把只支持渲染的库写成已经提供完整编辑器。

## 6. 页面行为

### 6.1 日记列表

- 按发生日期分组，同一天可显示多篇；组内默认发生时间倒序。
- 条目显示时间、可选标题/摘要、心情、标签及有图标记，点击打开记录。
- 新增日记与快速心情入口清楚可见；复用当前主题，技术诊断不占首屏。
- 草稿有可找回入口并标明“草稿”，不混充已发布记录。
- 空状态给出记录入口，不生成虚假日记。
- 支持日期范围、标签和正文/标题关键词组合筛选；标签多选明确提供“任一匹配/全部匹配”，计数和结果按记录ID去重。
- 关键词按普通文本处理，`%`、`_`等不得意外变成SQL通配符；查询使用绑定参数。
- 列表分页或增量加载，不一次读取全部图片原始字节。

### 6.2 日记编辑与详情

- 新建默认发生时间为当前时刻，可修改日期和时间以便补记。
- 标题可选；正文、图片、心情至少有一项才可正式保存，仅有标签的空记录不能误发布。
- 标签可多选并就地新建；心情可不选，未选择不能自动记成最低分或零分。
- 明确区分草稿保存状态与正式保存。手动保存成功后才反馈“已保存”和退出。
- 失败时保留编辑内容、图片预览和错误信息，不能关闭页面丢掉输入。
- 返回列表、安卓返回键、桌面关闭编辑页时，保留未发布草稿；全空新建页退出不产生垃圾条目。
- 删除需确认；编辑与删除操作完成后列表自动更新，无需重启。
- 详情支持Markdown预览、本地图片查看、编辑、删除；已删除记录不在普通列表出现。

### 6.3 自定义标签

- 支持新增、改名、选择颜色、解除关联和删除标签。
- 同名检测以统一规范化字段为准，至少处理首尾空白和英文大小写；不能新增空标签。
- 改名保持ID和既有引用不变；改成已有名称时提示冲突，不静默覆盖或合并。
- 删除标签仅解除关联/隐藏该标签，不删除日记、独立心情或图片。
- 情绪可用可选标签表达，例如“焦虑”“平静”；评分仍是单独的五档值，不根据正文自动推断。

### 6.4 快速心情

- 不要求输入日记正文，选择五档评分、发生时间和可选标签即可保存。
- 支持补记、查看、修改和删除，可在日记页通过心情筛选/切换入口查到。
- 独立快速心情不生成一篇空正文日记，也不藏在设置表里。
- 本批不画曲线，但数据必须支持未来按当天实际时刻排序展示。

## 7. 数据模型基线

按现有Room风格实现。表名可以调整，但语义和约束必须保留。

| 实体 | 关键字段 |
|---|---|
| DiaryEntry | UUID id、可选title、markdown、occurredAt、timeZoneId、createdAt、updatedAt、isDraft、deletedAt |
| MoodRecord | UUID id、可空diaryId、score 1～5、scaleVersion、occurredAt、timeZoneId、createdAt、updatedAt、deletedAt |
| Tag | UUID id、name、normalizedName、color、createdAt、updatedAt、deletedAt |
| DiaryTagCrossRef | diaryId、tagId，复合唯一键 |
| MoodTagCrossRef | moodId、tagId，供独立快速心情使用 |
| DiaryAttachment | UUID id、diaryId、relativePath、mimeType、byteSize、sha256、sortOrder、createdAt、deletedAt |

约束：

- 不以日期作为日记主键，不设“每天唯一”的索引。
- `MoodRecord.diaryId`可空且对非空值唯一：一篇日记最多关联一条心情；同一篇编辑评分更新原记录，不不断新增心情点。
- 独立心情的diaryId为null，可以同一天有任意多条。
- 无评分日记没有有效评分点。关联心情随日记使用同一发生时间，在同一事务中更新。
- 关联心情的标签从日记标签派生，不在两张关联表复制并独立维护；独立心情使用自己的MoodTagCrossRef。
- 删除日记同时逻辑删除关联心情和附件关系；不影响独立心情，不允许删除后留下有效评分点参与未来统计。
- 标签删除后，相关日记仍在；重新使用已逻辑删除的同名标签可恢复原ID，避免唯一索引冲突。
- 日记独立于课程表，删除课程或整个课表都不能级联删除日记。
- `createdAt`、`updatedAt`是系统时间；`occurredAt`是用户记录的实际时刻。补记只能改变发生时间，不能篡改创建时间。
- 时间以UTC时刻和时区ID保存，日筛选用该时区的本地日期边界转换；不能假设每天恒为24小时。
- 本批使用UUID、时间戳和删除标记预留后续同步，不引入完整因果版本/冲突引擎。

### 数据库升级

- 当前若仍v16，新增v16→v17迁移；如执行时版本已变化，按真实版本追加，不能覆盖其他迁移。
- 添加实体和DAO到MainAppDatabase，添加迁移到ALL_MIGRATIONS，提交新schema。
- 迁移只新增所需表和索引，保留课程、节次、日程、待办、设置等原数据。
- 主库禁止破坏性迁移、删库重建或要求用户卸载解决升级问题。
- 表结构、外键、唯一索引和默认值必须与Room导出的schema一致。

## 8. 图片与草稿的可靠保存

### 8.1 图片

- 通过现有FileManager选择图片，复制到应用管理的独立日记附件目录。不能仅保存相册URI、临时路径或源文件绝对路径。
- 数据库保存稳定附件ID与相对路径；通过当前AppStorage解析实际文件位置，跨设备后不能依赖旧电脑盘符。
- 建议Markdown引用采用 `![说明](attachment://<id>)`，预览解析为本地附件。不得自动上传图床。
- 使用随机ID防止同名图片覆盖；记录真实媒体类型和内容哈希，不把所有文件改后缀伪装成JPEG。
- 复用成熟编码/缩略图组件，限制单图体积并给出用户可理解的提示；加载缩略图避免三张大图直接耗尽内存。
- 写入采用临时文件→完成后改名，再提交数据库关系。失败回滚本次未提交关系，不删除已保存原图。
- 移除图片只解除本篇引用；物理文件回收必须确认没有其他有效引用和草稿引用。第一批可以延迟清理孤立文件，不能为省空间误删有效附件。
- 路径校验防止相对路径越界；读取不到附件时显示缺图状态，保留正文，不假装日记正常完整。
- 用户移动或删除原照片后，已保存日记里的图片仍可打开。

### 8.2 草稿与并发保存

- 输入暂停约500～1000ms后自动存草稿，页面退出时尽量flush；“已保存”只在实际提交成功后显示。
- 先持久化草稿身份，避免连续自动保存生成多篇草稿。
- 同一篇编辑按顺序保存或用修订序号校验，防止较慢的旧保存覆盖新输入。
- 自动保存与手动发布共享同一用例/串行机制；发布后迟到的草稿保存不能把它改回草稿。
- 事务同时保存正文、标签、心情与附件关系，不能正文成功、标签失败仍提示全部成功。
- 事务和文件不能假装跨系统原子；明确处理取消、写盘失败及数据库失败。
- 编辑器打开期间收到列表刷新，不得用数据库旧值重新灌入编辑框覆盖用户输入。

## 11. 备份和权限边界
