## 1. 决策摘要（ADR）

### ADR-001 客户端技术栈

**决定：Kotlin + Compose Multiplatform，共享领域层与 UI，交付 Android 与 Windows 桌面。**

备选与对比：

| 评价项 | Kotlin/Compose Multiplatform | Flutter |
|---|---|---|
| 旧版心晴复用 | 直接复用课程领域逻辑、例外、布局、测试 | 需全部重写 |
| 上课复用 | Apache-2.0；课程模型、xlsx 解析、导入启发式可按许可复用 | 需重写，且 .xls 解析生态弱 |
| Daily You 复用 | 不可复制（GPL-3.0）；只能参考交互 | 同样受 GPL-3.0 约束，复制会传染整个客户端 |
| Android 平台能力 | 精确闹钟、Keystore、文件选择、通知原生可用 | 依赖插件与平台通道 |
| Windows 桌面 | Compose Desktop 已被上游证明可打包 Exe/Msi | 成熟，但需要另建课程与导入能力 |
| Markdown/图表 | 需自建或选用 Compose 生态库，可控 | `markdown_widget`、`fl_chart` 成熟 |
| 许可风险 | 低：自有代码 + Apache-2.0 | 高：GPL-3.0 代码不可直接带入 |

**理由**：课程规则是最容易出错的领域，旧版心晴与上课两边都有 Kotlin 资产；Android 是一等交付目标；桌面与手机共用同一套 UI 符合“同等重要、先做手机端”的要求。Flutter 的优势主要在日记编辑体验，但该部分必须自研，无法抵消课程侧与许可侧的代价。

**后果**：

- 桌面端不是“另起炉灶”，而是同一共享 UI 的第二目标；P1 必须两个目标都真实构建。
- 日记 Markdown 编辑、图表需要自行选型/实现；P1 安排一次可丢弃 spike 验证中文输入、Markdown 手感与 Windows 打包。
- 不复制 Daily You 代码；交互与数据语义参考、独立实现。

### ADR-002 安装形态与数据

**决定：新包名 `com.hucw.xinqing2` 独立安装，不覆盖旧版；首版不做旧数据迁移。**

- 好处：与 1.x 并存、签名不冲突、升级失败有退路、可对照验收。
- 迁移：1.x 没有导出功能；用户已确认旧版只有课表、愿意在 2.0 手工重录，因此不开发迁移工具，也不改动旧仓库。
- 签名：沿用“CI 产未签名 APK + 本机固定密钥签名 + 指纹校验”的流程；是否复用旧 p12 在 P1 决定，禁止静默更换密钥。

### ADR-003 数据与同步

**决定：本地数据库为唯一事实源；同步采用“每设备不可变变更批次 + 提交标记 + 内容哈希附件”的协议，不使用整库覆盖。**

- 拒绝：两设备轮流上传同一 SQLite、仅按 `updatedAt` 取较新、把 WebDAV 上传成功当作合并成功。
- 冲突：不同记录直接合并；同一日记并发修改保留双方版本；删除与编辑并发进入待处理冲突。
- 加密：业务数据（日记、聊天、课程、日程、标签、附件）在上传前加密；协议元数据明文。恢复口令与恢复包都不存云端；两者都丢失则云端数据不可恢复，需在设置中明确告知。

### ADR-004 心情量表

**决定：五档 + 可选情绪标签；数据库保存原始评分与量表版本，图表按量表归一化。**

- 不把五档写死进数据库或图表坐标。
- 一篇日记最多一条关联心情记录，独立快速心情不受此限制；统计按记录 ID 去重。
- 日均值 = 当日有效评分之和 / 有效评分条数；周/月总体均值与“日均值再平均”分别命名。

## 2. 工程结构

```text
xingqing2.0/
  shared/                 # KMP：领域模型、规则、数据、共享 UI
    src/commonMain/kotlin/
      domain/             # 纯 Kotlin：重复、例外、统计、导入、同步合并
      data/               # 数据库、仓库、导入解析、同步协议
      ui/                 # Compose 共享界面
    src/androidMain/      # 通知、精确闹钟、Keystore、文件选择
    src/jvmMain/          # 桌面文件选择、凭据存储、打包入口适配
  androidApp/             # Android 壳与清单
  desktopApp/             # Compose Desktop 入口与打包
  cloud/reminder/         # 后续：提醒调度服务（P6）
  docs/
  .github/workflows/      # Android 与 Windows 构建、测试
```

分层：UI → 应用用例 → 领域模型/规则 → 数据与外部适配器。重复展开、统计、导入、同步合并不依赖 UI，也不依赖平台。

版本基线（P1 锁定，不跟随上游最新）：

- Kotlin 与 Compose Multiplatform：选择当前可稳定构建的组合。
- 数据库：Room KMP 或 SQLDelight；优先 Room（与 1.x/上课 一致，迁移测试成熟）。
- 序列化：kotlinx.serialization（JSON + CBOR）。
- 网络：Ktor（WebDAV、DeepSeek、提醒服务）。
- 依赖注入：Koin 或手写容器；首版倾向手写容器，减少编译期插件风险。
- JDK：桌面 21；Android 使用 CI 锁定的 LTS。

## 3. 构建与交付路线

### Android

- GitHub Actions：静态检查 → 领域/数据库/导入测试 → `assembleDebug` 产未签名 APK。
- 本机 `scripts/sign-apk.ps1` 用固定 p12 签名并核对证书指纹；只有已签名 APK 交付。
- `versionCode` / `versionName` / 包名 / 签名策略固定并记录；禁止 CI 缓存或上传私钥。

### Windows 桌面

- Compose Desktop `nativeDistributions` 产 Exe/Msi；P1 先决定便携版还是安装包。
- 数据目录放用户目录（如 `%APPDATA%/Xinqing2` 或用户自选），**不写入随版本替换的安装目录**。
- 新增 Windows CI job：构建、启动冒烟、产物上传；记录未签名/未签名的 SmartScreen 行为。
- 桌面升级必须保留数据；安装/卸载说明写入交付文档。

### 依赖与供应链

- 第三方 GitHub Actions 固定 commit 或可信版本，不使用 floating tag。
- 新增依赖核实维护状态、平台支持、许可证；GPL 依赖不得进入客户端，除非整体许可策略改变。

## 4. 数据模型草案

通用约定：

- 主键：UUID 字符串（客户端生成，离线可写）。
- 每条业务记录：`createdAt`、`updatedAt`、`deletedAt`（墓碑）、`schemaVersion`。
- 时间：存 UTC 时刻 + 必要的时间区/本地日期语义；日期型全天事件不用 UTC 零点伪装。
- 同步版本：设备 ID + 单调序列 + 父版本/因果信息，不用设备时钟判断新旧。

| 实体 | 关键字段 |
|---|---|
| Semester | id、名称、起始日、总周数 |
| TimeSlotScheme / TimeSlot | id、方案、节次、当地开始/结束时间 |
| CourseSeries | id、名称、教师、地点、学期、星期、节次或自定义时间、颜色、提醒 |
| CourseWeek | courseId、weekNumber（显式周集合，允许任意周） |
| EventSeries | id、类型（日程/待办）、标题、描述、起止/全天、截止、标签、重复规则、提醒 |
| RecurrenceRule | 频率、间隔、指定星期、截止日期或次数、月末策略 |
| OccurrenceException | 系列 ID、原始实例键、取消/改期/覆盖字段 |
| TaskCompletion | 实例 ID、完成状态、完成时刻 |
| DiaryEntry | id、Markdown、occurredAt、时区、createdAt、updatedAt、aiExcluded |
| MoodRecord | id、可选 diaryId（唯一）、原始评分、量表版本、occurredAt、标签 |
| Tag / EntryTag | 稳定标签 ID、名称、颜色、排序；多对多关联 |
| Attachment | id、内容哈希、媒体类型、大小、存储引用、排序 |
| DiaryEventLink | 日记 ID、事件/实例 ID、名称快照 |
| ChatSession / ChatMessage | id、角色、内容、生成状态、引用、会话归属 |
| ReminderRule / Delivery | 对象 ID、原始实例 ID、渠道、提前量、计划版本、发送状态 |
| SyncChange / Conflict | 设备 ID、序列、父版本、操作、变更/删除、冲突副本 |
| SharedSettings | 可同步偏好与版本 |

关键不变量：

- `MoodRecord.diaryId` 唯一（可空），保证“一篇日记一次评分只计一次”。
- 重复实例身份 = 系列 ID + 原始日期（+ 原始开始时间），例外不得丢失原实例身份。
- 课程“已结束”是时间状态，不等于用户“已完成”。
- 删除标签默认解除关联，不删除日记。
- 事件删除不级联删除日记。

## 5. 同步协议草案

云端目录（用户选择的根目录下）：

```text
xinqing-v2/
  protocol.json
  changes/<deviceId>/<sequence>-<batchId>.json
  commits/<deviceId>/<sequence>-<batchId>.json
  blobs/<encryptedObjectId>
  snapshots/<snapshotId>/...
```

流程：

1. 本地事务内同时写业务修改与待同步变更，避免“保存了但没入队”。
2. 先上传附件与批次，再写提交标记；下载端只应用“已提交且校验完整”的批次。
3. 拉取远端 → 本地待上传合并 → 再拉取一次，允许下一轮收敛。
4. 重传幂等；批次大小、分页、退避按服务限制设计。
5. 云端缺附件时保留记录与重试状态，不显示“全部成功”。
6. 定期快照与清理在协议稳定后实现。

冲突：

- 不同记录直接合并；同一日记正文并发修改保留两版并提示合并。
- 无共同基线不猜测；删除与编辑并发保留可恢复内容。
- 聊天消息独立 ID；生成中的消息带状态/版本，避免重复。
- 墓碑长期保留，清理依赖设备确认/快照协议。

加密边界：

- 加密后上传：日记、聊天、课程、日程、标签、附件、设置值。
- 明文：设备 ID、序列号、批次 ID、时间戳、对象引用等协议元数据。
- 恢复口令只存本机安全存储；提供恢复包导出；遗失后果明示。
- API Key、WebDAV 密码不进入普通同步包。

## 6. 微信提醒方案草案

职责：

- 客户端：编辑规则、提交计划版本、显示投递状态。
- 云端：持久化计划、到点触发、调用微信推送通道、记录结果与重试。
- 坚果云：只存同步数据，不做定时器。
- GitHub Actions：只做构建与测试，不做生产调度。

候选调度端（P6 前实测后定）：

| 方案 | 优点 | 风险/成本 |
|---|---|---|
| Cloudflare Workers + Cron | 接近零成本、部署简单 | 国内可达性与触发延迟需实测；免费额度限制 |
| 国内云函数 + 定时触发器 | 国内网络稳定 | 需要实名/计费；冷启动与配额需核实 |
| 小型 VPS | 可控、可观测 | 约每月固定费用；需要运维 |

推送通道：优先评估 Server酱等微信推送服务；购买/部署前用用户账号发一条真实测试消息，核实额度、费用、消息展示位置与频率限制。

费用与调度结论见 `docs/提醒费用方案.md`：拟采用 Cloudflare Workers 免费层 + Server酱 年费会员，常态月成本约 3.25 元；若国内连通性不达标，切换阿里云函数计算。P6 前用真实账号实测。

可靠性：

- 幂等键：对象 ID + 原始实例 ID + 渠道 + 提前量 + 计划版本。
- 编辑/取消/完成待办后提交新版本或取消指令；旧任务按版本失效。
- 离线修改先本地保存，显示“云端提醒尚未更新”；联网后替换。
- 分别记录“调度触发 / 通道接受 / 实际送达”；HTTP 200 不等于手机收到。
- 过期提醒策略可配置：短延迟可补发，过时课前提醒不再轰炸。
- 定期续排未来窗口，不依赖用户每天打开应用。

## 7. AI 方案草案

- 配置 DeepSeek 官方 API 地址、模型与 Key；连接测试；Key 存设备安全存储。
- 工具只读：`getDiaryEntries`、`searchDiaryEntries`、`getMoodSeries`、`getDiaryContext`；课程/日程查询默认关闭，用户授权后启用。
- 访问过滤在数据层执行；日记正文视为资料而非指令；提示词不能扩大权限。
- 限制调用轮数、返回条数、时间范围与上下文大小；统计由应用计算，模型只解释。
- 引用必须映射到实际返回的记录 ID；不存在的 ID 不渲染。
- 流式显示、停止、重试；失败保留用户消息与已收内容，重试不重复插入。
- 向量检索与长期记忆放 P8；索引可本地重建，删除/排除 AI 后及时失效。

## 9. 决策记录

### 已确认

1. **.xls 策略**：首版只支持 .xlsx + 文本类格式；遇到 .xls 给出“请另存为 .xlsx”的清晰提示。不引入 BIFF 解析库。
2. **1.x 数据迁移**：旧版只有课表且用户愿意重录；不做迁移工具，不修改旧仓库。
3. **客户端技术栈**：Kotlin + Compose Multiplatform。
4. **开发顺序**：先手机端；桌面同等重要，P1 两个目标都真实构建。

### 待确认

1. **提醒渠道与月预算**：已确认采用 Server酱 年费会员 + Cloudflare Workers 免费层作为首选，常态月成本约 3.25 元；P6 实测不达标时切阿里云函数计算。详见 `docs/提醒费用方案.md`。
2. **桌面交付形态**：便携版 + 数据目录，还是 MSI 安装包；P1 验证打包链后二选一。
3. **产品默认值已确认**：五档 + 情绪标签；业务数据端到端加密；AI 默认只读未排除日记，课程/日程默认关闭。
