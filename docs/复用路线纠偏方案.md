# 接手与复用路线纠偏方案

日期：2026-11-16。状态：用户已确认以上课完整客户端为底座；已导入 client/，首批适配待当前提交 CI 验证。

## 1. 推荐决定

推荐以“上课”完整客户端为底座扩展心晴，保留成熟页面、数据仓库和主题组件，逐步增加日记、心情、AI、同步和云端提醒。不再以当前简化 UI 为基线。

上游固定版本：`afd1389cfaef2be15cef0aea7ea4efa158f1659e`。

当前心晴基线：`993025f`。接手时仅需求任务书有用户未提交修改，必须保留；本轮未操作用户桌面、未启动应用、未运行构建、未推送远程。

## 2. 为什么推荐此路线

实际读取 `AgendaScreen.kt`、`AgendaViewModel.kt`、`App.kt` 和构建文件后的结论：上课日程页不是一个孤立 Composable，而是完整功能模块的一部分。

- UI 依赖 AppCard、AppPageHeader、AppTextField、AppGlassBottomSheet、日期/时间选择器、Haze、动效与触觉反馈适配。
- 样式依赖 appColors、appSpacing、appType、appShapes 等统一设计系统。
- 文案与图标依赖 Compose 生成资源。
- ViewModel 使用 Koin 和 lifecycle，读取课表、节次、日程、待办、设置仓库；已经将课程、日程、待办合并到同一页面。
- 数据仓库依赖现成的 Room 数据模型、DAO、设置与日期流。

直接抽一个页面接入当前手写 SQLite 仓库，会引发组件、资源、数据语义的持续适配。保持原有模块一起工作，更符合用户优先保留原版体验的要求。

| 路线 | 可直接保留 | 额外工作 | 建议 |
|---|---|---|---|
| 以上课完整客户端为底座 | 课程/日程/编辑/导入、主题组件、数据层、主导航基础 | 心晴品牌与包名、CI、安全适配、新增模块、隐藏无关入口 | 推荐 |
| 整体模块移入当前工程 | 可保留选定页面 | 迁移大量组件/资源/仓库，维护两套模型或复杂适配器 | 不优先 |
| 继续重写课程和日程 UI | 当前简化骨架 | 重新实现成熟交互，增加回归风险 | 停止 |

这是源码依赖调查后的工程判断，尚未实测完整上游在本项目 CI 中的构建；不能承诺原封不动复制后立即编译成功。

## 3. 精确复用入口

以下路径相对上游仓库：

| 功能 | 源码入口 | 保留策略 |
|---|---|---|
| 课程与日程统一页面 | `shared/src/commonMain/kotlin/com/shangkeschedule/ui/agenda/AgendaScreen.kt` | 保留月份展开、日期轴、条目展示、创建底部面板与完成交互 |
| 三类数据合并 | 同目录 `AgendaViewModel.kt` | 保留数据流及原有查询，新增重复实例时扩展数据来源 |
| 今天概览 | `ui/today/TodayScheduleScreen.kt`、`TodayScheduleViewModel.kt` | 原样保留作为参考；先让统一日程页成为心晴核心入口 |
| 周课表 | `ui/schedule/` | 保留周视图、课程展示及对应编辑入口，不重建时间网格 |
| 文件导入 | `ui/settings/import/` | 保留文件识别、预览与实际提交流程 |
| 导入解析 | `data/parser/ExcelScheduleParser.kt`、`UniversalScheduleParser.kt`、`ImportFormat.kt` | 直接复用现有解析器和边界保护，补匿名样本回归 |
| 课程数据 | `data/db/main/Course.kt`、`CourseWeek.kt`、`TimeSlot.kt` | 保留显式周集合和节次模型 |
| 日程和待办数据 | `data/db/main/ScheduleEvent.kt`、`TodoItem.kt` | 保留已有数据和完成逻辑，重复功能增量迁移 |
| 页面组件和视觉风格 | `ui/components/`、`ui/theme/`、Compose资源目录 | 与页面一起保留；不替换为默认表单 |
| 导航与依赖注入 | `App.kt`、`Navigation.kt`及DI入口 | 在原有机制中增加心晴入口，初期不另造导航框架 |

日程页实际已有 `AgendaDatePanel`、`AgendaDateRail`、`AgendaMonthGrid`、`AgendaEntryRow`、`AgendaCreateSheet` 等函数。原版不是当前心晴新写的全天分钟网格；开发中不能仅保留“时间轴”字样就宣称还原原版。

## 5. 仍然需要新增的能力

- 重复日程和单次例外：扩展现有日程实体/查询，完成状态仍按实例处理。
- Markdown图文日记、标签与一次一条的心情记录。
- 日内心情变化、周/月和标签统计、记录跳转。
- DeepSeek聊天、授权范围、只读检索工具和引用。
- 坚果云双向合并与冲突处理。保留原版备份能力不等于已经实现同步。
- 微信云端调度。与原版本地通知区分。

旧调查中“Daily You 是 GPL 所以不能复制”的绝对说法不应当作最终技术结论。GPL本身并非禁止复制；是否复用要结合许可条件和最终分发方式核实。当前路线不需要引入 Flutter；日记编辑器先选兼容 Compose 的成熟方案，不因原有错误表述强制全部自研。

## 6. 用户确认路线后的首个开发批次

1. 保存当前基线及所有未提交工作；通过明确的文件清单导入固定版本上游源文件，排除其 `.git`、工作日志、缓存、构建产物、私有配置及与心晴无关的发布工具。
2. 保留许可证与来源记录；不搬用上游代理指令来覆盖心晴开发要求，不触发其网站、推送或学校适配发布流程。
3. 保留原代码内部包路径以减少无意义改名；Android applicationId 继续使用心晴独立包名，应用名称/版本与桌面数据目录改为心晴。避免误覆盖原版上课用户数据。
4. 初批先保持课程/日程/文件导入原有能力；无关功能先隐藏入口，不大面积物理删除代码制造连锁编译问题。
5. 将统一日程页设置为核心入口，沿用原版样式；不在此批加入AI、同步和图表。
6. 适配现有 Android/Windows CI：不运行桌面GUI；海外运行器需按上游配置使用 `-PuseMirror=false`，避免无关镜像故障。
7. 编译、相关原有测试、产物检查通过后，下载并签名 Android APK；提供 Windows 包。没有授权不启动桌面应用。
8. 由用户验证是否保留了喜欢的日期面板、时间轴和创建操作，再进入下一批增量功能。

首批验收：能安装；原版课程管理和文件导入可用；核心日程页面保留原版交互；应用包名与数据目录独立；旧dev数据不被静默删除。构建通过和用户体验通过分别记录。
